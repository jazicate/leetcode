### Step 1: Understand the Problem
Ask yourself:
- What is the input?
- What is the output?
- Are there constraints?
- Edge cases?

Example:
```
Input: [1,2,3,4]
Output: ?
Constraints: n <= 10^5
```

### Step 2: Do Brute Force Approach First
Always start with the simplest idea.

Example thought process:
```
Can I check all combinations?
Can I use nested loops?
```

Even if it's slow.

This helps you understand the structure.

### Step 3: Identify the Pattern
Ask:
- Is this a **hashmap problem?**
- **Two pointers?**
- **Binary search?**
- **Sliding window?**

Good engineers recognize **patterns quickly**.

### Step 4: Optimize
Reduce:
- Time complexity
- Space complexity

Example:

| Approach    | Complexity |
| ----------- | ---------- |
| Brute Force | O(n²)      |
| Optimized   | O(n)       |

### Step 5: Write Clean Code
Focus on:
- Edge cases
- Clean logic
- Readable code

### Step 6 — Analyze Complexity
Always state:
```
Time Complexity: O(n)  
Space Complexity: O(1)
```

Interviewers expect this.
