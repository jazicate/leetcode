## Best Order to Learn LeetCode
Follow this order:
```
1 Arrays  
2 Hashmaps  
3 Two Pointers  
4 Sliding Window  
5 Stack  
6 Binary Search  
7 Linked Lists  
8 Trees  
9 Heap  
10 Graphs  
11 Dynamic Programming
```

Many DSA roadmaps start with **arrays and strings before moving to more complex structures**.

## How Many Problems Per Day?
|Stage|Problems/day|
|---|---|
|Beginner|2|
|Intermediate|3–4|
|Advanced|5|
Consistency is the most important factor.

Reddit advice commonly suggests solving **at least a few problems daily**.

---
## Best Strategy to Learn FAST
Follow the **30-minute rule**:
1. Try problem for **20–30 minutes**
2. If stuck → check solution
3. Understand approach
4. Re-code from memory

Never just read the answer.

## The Real Secret to LeetCode
The real trick is **pattern recognition**.

After ~150 problems you start thinking like this:
```
"Ah this is sliding window"  
"This is binary search"  
"This is DFS"
```

And then the solution becomes obvious.

## Common Beginner Mistakes
### 1. Doing random problems
Follow structured lists.

### 2. Memorizing code
Understand patterns instead.

### 3. Spending 3 hours stuck
Use the **30 minute rule**.

### 4. Not reviewing old problems
Repeat problems weekly.

---
## Pattern Recognition Cheat Sheet

|If you see this|Use|
|---|---|
|Subarray / substring|Sliding Window|
|Sorted array|Binary Search / Two Pointers|
|Frequency / duplicates|HashMap|
|Tree / graph|DFS or BFS|
|Cycle detection|Fast & Slow pointers|
|Top K elements|Heap|
|Permutations / combinations|Backtracking|
|Optimization problem|Dynamic Programming|
